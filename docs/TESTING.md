# 测试与验收说明

本地完整版本和在线Demo分开测试。以下用例使用虚构信息；“建议目标”是验收标准，不是已达到的性能承诺。

## 1. 准备材料

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe .\scripts\create_test_materials.py
```

输出位于 `test-materials/`：

- `通知.txt`：两类申报、截止时间、命名要求和可选字段。
- `研究探索申请表.docx`、`社会实践申请表.docx`：对应的空白模板。
- `标准材料.zip`：通知、两个模板和CSV参考材料。
- `混合材料.zip`：Word、文字与一个不支持类型，验证逐文件导入。
- `预期结果.json`：事项、填写信息、可选字段、不可填写字段和文件名。

额外生成真正的旧DOC及其ZIP，需要本机Word/WPS转换环境可用：

```powershell
.\.venv\Scripts\python.exe .\scripts\create_test_materials.py --with-doc
```

生成失败先检查Office转换环境；不要通过修改扩展名把DOCX伪装成DOC。该目录为可重新生成的测试数据，已加入Git忽略。

## 2. 自动回归

### 本地完整版本

在项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Mode test
```

也可指定独立临时目录，便于保留每次结果：

```powershell
.\.venv\Scripts\python.exe -m pytest -q --basetemp=.test-tmp-acceptance
```

覆盖附件解析、会话关联、表单填写、文件命名、结果回传逻辑、账号隔离、绑定消息、编辑会话和网络路由等。部分外部服务使用替身，测试通过不表示已经访问真实飞书、模型或ONLYOFFICE。

### 在线Demo源码

先安装Node.js 22.13+及依赖，**进入 `online-demo/` 目录**：

```powershell
cd online-demo
node --experimental-strip-types scripts/check-demo.mjs
node --experimental-strip-types scripts/check-uploads.mjs
node --experimental-strip-types scripts/check-conversion-timeout.mjs
node node_modules/typescript/bin/tsc --noEmit
npm run build
```

覆盖ZIP往返、危险路径、中文文件名、混合ZIP部分成功、接口参数、模板位置过滤、密钥不返回客户端及等待超时逻辑。浏览器转换引擎、下载网络和真实模型质量仍需人工验收。超时检查针对当前源码，不应据此推断旧的线上部署已更新。

## 3. 本地人工验收

先按根目录README启动网页并登录，确认已配置真实模型。

1. **L01 通知与模板匹配**：新建本地任务，粘贴 `通知.txt` 并上传两个DOCX，开始解析。应识别“研究探索”和“社会实践”，选不同事项应匹配不同模板，截止时间为2026-12-01 18:00。
2. **L02 选择、填写与生成**：选研究探索，按 `预期结果.json` 填写。获奖情况留空应允许继续；组织审核意见不应要求申请人填写。未人工确认前不得生成最终申请文件。
3. **L03 Word内容和版式**：确认生成后用Word/WPS打开，核对每个值的位置、中文、表格行列、合并单元格、标题及分页。检查文件名为 `测试同学+DEMO2026001+研究探索.docx`，没有残留示例值或把提示文字写进个人总结。
4. **L04 旧DOC**：使用 `--with-doc` 生成的文件重复L01～L03；应保留原表格结构。复杂模板另做分页和字体检查，不能仅凭成功下载判定通过。
5. **L05 填写助手（仅本地完整版本）**：有排名/总人数和百分比两个字段的模板中输入“第2名，共30人，请填写排名百分比”。预期比例6.67%，排名仍为2/30；个人总结只能根据已提供事实起草，不得虚构获奖。
6. **L06 状态与修改**：生成后手动确认完成，任务应显示已确认；重新修改或解析后需重新检查确认。在线编辑另需启动Docker及编辑服务，保存返回结果页后下载与预览都应使用最新版。
7. **L07 账号隔离**：A、B分别注册账号创建任务。B的列表不能出现A的任务；B访问A的任务链接、附件、导出接口应被拒绝。退出登录后也不能读取材料；个人资料不能跨账号自动带入。
8. **L08 异常输入**：缺少所选类别的必要模板、损坏文件、超限附件和扫描PDF无视觉模型分别测试。应明确说明缺失/未读取原因，不得假装已经完整解析或生成成功。

## 4. 飞书企业联调

确认使用同一测试企业/应用环境的凭证、权限、事件和群；网页与长连接两个进程均在线。

1. **F01 绑定**：网页获取绑定码，由本人在群里@机器人发送；应绑定成功，且不新建任务。过期码、重复码和他人已绑定身份不能覆盖现有绑定。
2. **F02 消息与文件**：@机器人发送测试通知，回复收集提示“开始上传”，收到确认后普通发送 `标准材料.zip`；机器人和网页的附件数量应一致。再回复“开始解析”，通知和附件应属于同一个任务。
3. **F03 两人同时使用**：A、B在同一测试群分别创建上传会话并发文件；按发送者分别关联，不得串任务。各自网页只显示自己的任务。
4. **F04 文件回传**：生成、检查并点击发送，群内应收到真实Word附件；文件名、填写内容与网页最新版一致，发送后状态正确。在线编辑后再发一次，确认不是旧文件。
5. **F05 权限缺失**：在可恢复的测试环境中分别检查只有@权限、未订阅接收消息、长连接停止等情况。应能从页面/日志定位原因；恢复配置后用新消息复测，避免把历史消息未重推误判为失败。

飞书凭证不是登录账号密码。外部账号能看到机器人名称，不代表已在测试企业和应用可用范围内；先核对企业身份和测试人员配置。群内附件本身仍对该群成员可见，不属于网页账号隔离范围。

## 5. 在线Demo人工验收

打开README中的公开链接，使用桌面Chrome/Edge：

1. **D01 免配置示例**：点击“体验示例”，选择、填写、确认、下载Word；该路径验证交互，不计入真实模型识别准确率。
2. **D02 真实模型**：粘贴生成的通知，上传两个DOCX；无需输入Key，应返回两类事项和对应表单。确认前不得自动提交到其他平台。
3. **D03 混合ZIP**：上传 `混合材料.zip`；两个Word和TXT应保留，不支持的成员单独提示，不能整批消失。另测中文目录与文件名。
4. **D04 DOC冷启动**：新浏览器配置或清理站点缓存后上传 `旧DOC材料.zip`，选择“研究探索”，记录引擎准备、下载和转换耗时；首次约30MB下载需单独计时。生成后检查中文、表格和值。该ZIP仅带研究探索模板，若选社会实践，应提示缺少对应模板。
5. **D05 DOC热启动**：同一浏览器重新打开页面再上传DOC，验证缓存复用；重复3次。不要把冷启动下载时间与缓存后的转换时间混在一起。
6. **D06 弱网和失败**：网络较慢、资源不可达、损坏DOC分别测试。应出现可理解的阶段/失败信息，最终结束等待，不能长期锁住整页。当前线上若仍只有“正在准备”而无阶段提示，应记为待排查，不能记录为通过。
7. **D07 隐私与导出**：刷新后材料应清空；不同浏览器不共享材料。开发者工具中不应出现服务端模型Key；模型接口只返回业务结果。下载后Word能打开，且值在正确单元格。

## 6. 指标如何统计

建议准备至少20份不同通知/模板，按DOCX、DOC、混合ZIP和异常输入分组；先由人工标注正确事项、字段和模板。提供的两类样例只用于冒烟测试，不足以证明通用准确率。

- **端到端成功率**＝无需修代码即可完成确认、生成并打开Word的有效样本数 ÷ 有效样本数。初期建议目标≥95%；不支持格式单列，不能悄悄从失败记录中移除。
- **事项识别精确率/召回率**：正确识别的事项数分别除以系统输出事项数、人工标注事项数。分别记录误报与漏报，建议二者≥95%；截止时间与命名规则单独核对。
- **字段正确率**＝标签、含义及目标位置均正确的字段数 ÷ 人工标注可填字段数；额外误识别字段另计。姓名、学号、类别等关键字段和模板匹配在验收集上要求100%正确；选填字段不应误标必填。
- **Word内容与版式**：关键值位置正确率100%；逐份检查表格结构、合并格、中文、标题、分页和审核栏。需人工调整分页的样本单列，不算“原样保留通过”。
- **隔离与确认**：跨账号读取成功次数必须为0；未经人工确认生成/发送次数为0；两人附件错配次数为0。
- **耗时**：分别记录导入、模型解析、生成、飞书回传；DOC另外记录冷启动下载与热启动转换。每组至少20次报告P50和P95，注明硬件、浏览器、网络、模型名、文件大小和是否命中缓存。初期可把小文件模型解析P95≤90秒、热启动转换/生成P95≤30秒作为观察目标，超时与失败必须计入报告，不能只统计成功请求。
- **成本**：记录真实模型调用次数、服务商返回的输入/输出token和账单费用；按单任务和整次测试汇总。没有返回token时标记未知，不根据页面字数伪造精确费用。
